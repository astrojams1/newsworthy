# v23: a preview says what the release will settle

On 2026-10-14 the owner flagged reading 1209 as "almost clickbait because it
doesn't state upfront the salient takeaway": "The US releases September consumer
price figures today, the first since the Fed raised interest rates last month."
It was saved at 01:04 UTC, eleven hours before the release, and the app showed
it with "New:". Shipped text: version 23, hash `51dc90c54eed7bad`, 2,296
characters.

## The pattern in production

All v18 to v22 readings from 2026-09-14 to 2026-10-14 (397), read through the
admin history. About 15 headline a scheduled event that has not happened yet:

- Under v20, twelve: the Sep 30 inflation report (866–871) and the Oct 2 jobs
  report (911–916, 919). Every one carried its stake in a forecast tail:
  "US inflation data due today could decide if the Fed raises rates in Oct"
  (869), "A US jobs report due today could jolt stocks and mortgage rates"
  (916).
- Under v22, three: 1020 (Bank of Japan speech "later today, with traders
  watching for hints of a second interest rate rise"), 1030 (a Treasury bond
  sale "this week") and 1209.

**Cause.** Three things stack.

1. Summary asks for "the development most likely to cause" a sharp move. On
   the morning of a data release that is the release itself, before it has a
   result.
2. v21 cut the forecast tail, rightly, but for a preview the tail was the only
   part that said why it mattered. What is left is the set-up.
3. "One development, who did what" has nothing to say about an event no one
   has done yet. The rater filled it with "The US releases".

## What changed from v22

Output only. One clause after "Never predict market moves.":

> Before scheduled news, lead with what it will settle.

"Settle" names the question the release answers without guessing its answer,
so the clause stays inside rule 9. The clause took v22 from 2,295 to 2,349
characters. To fit rule 7, Output was tightened without changing what it asks
for:

- "Reply with a single JSON object and nothing else, no prose or fences:"
  became "Return only this JSON, no prose or fences:".
- "5 of them for the app's" became "5 for the app's".
- "dates, years and ordinals don't count" became "dates, years, ordinals
  don't count".
- "market figures and uncommon acronyms" became "market figures, rare
  acronyms".
- "(year only if not this one, no weekdays)" became "(no year if this one,
  no weekdays)".
- "rating justification or advice" became "rating justification, advice".

Everything before Output is v22's verbatim. Rule 11 in `PROMPT-RULES.md`
requires the clause in every later version.

## How it was tested

Claude Code subagents, each started fresh with the Agent tool's `opus` model
alias, the model family the hourly caller runs. The alias resolves to the
current Opus release; this record does not pin its version. Generation
settings were the harness defaults: the Agent tool exposes no temperature,
sampling or token settings, so none were set. Fixture agents had file read
only, no web search; live agents had WebSearch, WebFetch and curl. Nothing was
submitted.

The first round (fixture runs v23 A and B, live runs 1 and 2) ran a draft,
hash `b990e48960c3b2c8`, that carried the same new clause but tightened
differently: "Reply with only this JSON", "at most 140 characters with spaces
and punctuation", and "rating justification or advice" unchanged. A caller
test pins the "including spaces and punctuation" unit, so the shipped text
keeps it and finds the room elsewhere. The shipped text was then re-run (v23
C and D, live run 3, below).

### Fixtures: same notes, v22 and v23 Output

Ten fact notes in `v23-fixtures.md`. S1–S5 are scheduled releases not yet out:
the CPI morning of reading 1209, a Bank of Japan speech, a Treasury bond sale,
Fed minutes and a jobs report. S6 is a forecast storm, scheduled by nobody, to
see whether the clause spreads to what it should not. C1–C4 are developments
that happened, as controls. Two agents per version wrote one sentence per note
following only that version's Output.

| Run | S1 CPI | S2 BoJ | S3 bonds | S4 minutes | S5 jobs |
|---|---|---|---|---|---|
| v22 A | no | hint | no | no | no |
| v22 B | no | hint | no | no | no |
| v23 A | yes | hint | yes | weak | weak |
| v23 B | yes | yes | yes | weak | weak |

"Hint" means the stake is a trailing aside about what traders watch, not the
lead. "Weak" means the sentence leads with the release but the stake is
generic ("will show its thinking", "will show September hiring").

Both v22 runs reproduce reading 1209 on S1: v22 A wrote it almost word for
word. Both v23 runs put the question first: "Today's US inflation report will
show whether prices kept speeding up after the Fed raised interest rates in
September" (A), "…will help settle whether it raises them again Oct 28" (B).

S6 and C2–C4 read alike under both versions: the clause did not spread to the
storm forecast or to news that happened. On C1, the inflation result, both v23
runs added the reported shift in trader odds ("traders now see a Fed rate rise
as likely"), which the note states and v22 left out. That is reported pricing,
not a forecast of a market move. No output in any run carries a market
forecast or an agentless passive, and all are within 135 characters.

## Limits

- Fixture notes are reconstructed from stored readings and are not
  independently checked reporting. Two runs per version.
- The stake is sometimes generic for Fed minutes and a jobs report, and one
  of four runs left the bond sale and the minutes as plain set-ups. The clause
  reliably fixes the inflation-report case; for lesser releases it helps
  without guaranteeing.
- Whether the hourly caller writes previews this way is established only by
  naturally arriving v23 readings with `prompt_verified: true`.
- Not changed: the judge still opens a new development for a preview, so the
  app labels it "New:". That is a judge decision, outside this version.
- Scores are not evidence about calibration. The scale is unchanged.
