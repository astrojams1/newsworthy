# v24: dates, never relative days

On 2026-10-14 the owner's widget showed "10h ago: US inflation figures due
today will show whether prices are rising fast enough for the Fed to raise
interest rates again." and read it as overdue. Shipped text: version 24, hash
`a9791807609fb232`, 2,296 characters.

## The pattern in production

The sentence came from reading 1212, saved at 04:03 UTC, which was 9:03 p.m.
Pacific on Oct 13. "Today" meant Oct 14 in UTC. Ten hours later the widget
dated it "10h ago", which put it in the reader's previous evening, so "today"
read as Oct 13 and the release as past. It was still due at 8:30 a.m. Eastern.

Relative day words (today, tonight, tomorrow, yesterday, this morning) in
readings from v18 on, through 11:04 UTC Oct 14:

| Prompt | Readings | With a relative day |
|---|---|---|
| v19 | 50 | 1 |
| v20 | 127 | 12 |
| v22 | 213 | 6 |
| v23 | 8 | 7 |

v23 made it common. It asks a preview of scheduled news to lead with what the
release will settle, and the rater names the release as "due today".

## What changed from v23

Output only. The style line's "(no year if this one, no weekdays)" became
"(no year if this one, no weekdays or relative days)". Dates were already the
style ("Jan 10, Oct"). To fit rule 7:

- "Return only this JSON, no prose or fences:" became "Return only this JSON,
  no fences:". "Only this JSON" already rules out prose.
- "Submit no label." became "Omit it."

Everything else is v23's. Rule 12 in `PROMPT-RULES.md` requires the entry in
every later version.
